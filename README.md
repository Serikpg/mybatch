# Slurm Local Broker Daemon

A lightweight, C++ based local job broker for Slurm environments that enforce strict QoS policies like `MaxSubmitJobs=1`. 

This tool acts as an intermediary queue. It allows you to submit multiple `sbatch` scripts locally, and a background daemon ensures that at most **one** job is actively queued or running in Slurm at any given time for your user.

## Features

- **Persistent Queue:** Uses an embedded SQLite database (`~/.slurm_queue/queue.db`) to preserve job states across SSH disconnects and shell restarts.
- **Background Daemon:** Actively polls Slurm (`squeue`, `sacct`) and dispatches jobs only when your active job count drops to zero.
- **Retry Mechanism:** Features exponential backoff if a transient node error causes `sbatch` to fail.
- **Client Binaries:** Includes lightweight, non-blocking CLI tools mimicking standard Slurm commands (`mybatch`, `mycancel`, `mystatus`, `mylogs`).

## Dependencies

- **C++17** compatible compiler (GCC/Clang)
- **CMake** 3.10+
- **SQLite3** (`libsqlite3-dev` or similar package)
- **Slurm Workload Manager** (`sbatch`, `squeue`, `sacct`, `scontrol` available in `$PATH`)

## Build Instructions

1. Clone or navigate to the repository directory.
2. Generate build files and compile:
   ```bash
   mkdir -p build
   cd build
   cmake ..
   make -j4
   ```

## Usage

All compiled binaries will be placed in the `build/` directory. You may want to add this directory to your `$PATH`.

### 1. Start the Server Daemon
Run the server daemon in a persistent session (e.g., `tmux`, `screen`, or as a systemd service). It will continuously monitor the local queue and Slurm status.
```bash
./mybatchd --interval 15
```
*(Default polling interval is 15 seconds).*

### 2. Submit Jobs
Use `mybatch` to add scripts to your local queue. It accepts the path to an `sbatch` script and returns immediately.
```bash
./mybatch /path/to/script1.sh
./mybatch /path/to/script2.sh
```

### 3. Check Queue Status
View all locally queued, running, and completed jobs, along with their associated Slurm Job IDs.
```bash
./mystatus
```

### 4. View Logs
View the `stdout` and `stderr` generated by a specific local job execution. The daemon automatically tracks where Slurm writes the logs.
```bash
./mylogs <local_id>
```

### 5. Cancel a Job
Cancel a local job. If the job is actively running or pending in Slurm, this will also invoke `scancel` natively.
```bash
./mycancel <local_id>
```
